# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Weather agent** (`weather-agent/Andes.Agents`): a production-oriented ASP.NET Core host for a Microsoft Agent Framework weather agent, reachable over both [A2A](docs/agent/hosting-and-protocols.md#a2a) (HTTP+JSON and JSON-RPC) and [AG-UI](docs/agent/hosting-and-protocols.md#ag-ui), and secured end to end with Microsoft Entra ID. Conversations persist to Azure Cosmos DB — one document per session and one per message — so a caller can resume a conversation across turns and browse or delete their own conversation history through a new `api/conversations` REST resource. Includes three weather tools backed by a deterministic in-process data source, OpenTelemetry tracing and token-usage metrics exported to Azure Monitor, per-caller rate limiting, and an OpenAPI/Scalar reference UI. See [docs/README.md](docs/README.md) for the full documentation set.
- A second, optional model provider: `MicrosoftFoundry` configuration registers a Chat Completions client on the same Azure AI Foundry resource and route as the agent's, for a future caller that needs a plain model call rather than an agent turn. Leaving it unconfigured registers nothing and doesn't affect startup.
- Global per-request logging (`RequestLogging` configuration) writes one line per request — method, matched route, status, elapsed time — without ever recording a body, prompt, query value, or the caller's Entra object id.
- Every problem+json error response now carries `traceId` (the Application Insights operation id) and `requestId` (the id the server's own log lines carry for that request), so a caller-reported failure can be found in telemetry and logs without exposing any request content.
- The `/scalar` reference UI can now sign a caller in through Microsoft Entra ID instead of only accepting a pasted bearer token: set `ApiDocs:ClientId` (and `ApiDocs:Scopes`) and Scalar offers an `EntraId` option using PKCE with no client secret, returning the authorization code in the URL fragment so it never reaches request logs or telemetry. Leaving `ApiDocs:ClientId` blank keeps the previous bearer-only behavior. See [Configuration](docs/operations/configuration.md#apidocs) and the [runbook](docs/operations/runbook.md#configure-user-secrets) for the Entra ID app registration steps.
- A second, relational store: SQL Server 2025 through EF Core 10, holding one entity, `[Core].[Policy]`, in a new `Andes.Agents.Repository/Sql/` provider folder alongside the existing Cosmos DB one. It ships production-shaped — generated migrations, five check constraints, a unique and a covering secondary index plus a composite renewal/expiry index, `rowversion` optimistic concurrency, audit timestamps stamped by a save interceptor, connection retry, and a `sql` readiness check — but database-layer only for now: no repository, service, or endpoint reads or writes a policy yet. `SqlDb` is a required configuration section (its connection string lives at `ConnectionStrings:DefaultConnection` — see below) and `/health/ready` now depends on SQL Server as well as Cosmos DB. See [Architecture overview](docs/architecture/overview.md#the-corepolicy-table), [Configuration](docs/operations/configuration.md#sqldb--the-policy-database), the [runbook](docs/operations/runbook.md#start-sql-server-2025) for running it locally and generating migrations, and [ADR-0002](docs/adr/0002-sql-server-policy-store.md) for why.
- A database-owned agent catalog and SQL Server session-usage reporting: three new tables under `[Core.Ref]` (agents, model deployments with USD prices per million tokens, and which model each agent currently runs) and one under `[Core].[Session]`, holding cumulative token counts and an estimated cost per session incarnation. A migration seeds the catalog's defaults — there is no configuration section for it, and the app never writes it, only reads it through a 24-hour in-memory cache. A background writer projects each session's usage into `[Core].[Session]` after it's saved or deleted in Cosmos DB, pricing only the growth in tokens at the catalog's current price so cost stays exact under retries and partial writes. Startup now fails unless every hosted agent has an active model that matches its configured chat-client deployment, making SQL Server a required dependency at startup, not only at `/health/ready`. See [Architecture overview](docs/architecture/overview.md#the-agent-catalog-and-session-usage-summaries), [Sessions and history](docs/conversations/sessions-and-history.md#session-usage-reporting), [Configuration](docs/operations/configuration.md#the-agent-catalog-is-not-configuration), the [runbook](docs/operations/runbook.md#changing-the-agent-catalog) for changing a price or a model, and [ADR-0003](docs/adr/0003-database-owned-agent-catalog-and-session-usage.md) for why.
- **Angular UI workspace** (`agents-ui/`): a new Angular 22.1 client for the agents platform, zoneless by default and laid out by a new dependency-direction rule (`.claude/rules/ui-architecture.md`) that ESLint enforces automatically as features are added. It's configured, not yet a product — an app shell styled in the Andes brand palette (Summit Navy, Ink, Glacier Blue, Andes Green, Slate and Snow) across light and dark themes, a theme toggle backed by an NgRx SignalStore, one lazy home page, and no `HttpClient`, auth, or dev proxy to `agents-api/` yet. Ships with the checks a real feature will run against: Vitest unit tests, Prettier with a fixed import order, and a build gate that fails if a page or feature file leaks into the app's initial bundle. See [docs/ui/angular-workspace.md](docs/ui/angular-workspace.md).

### Changed

- Moved the policy database's connection string from `SqlDb:ConnectionString` to the ASP.NET Core standard `ConnectionStrings:DefaultConnection` key, so it lines up with the environment-variable and Azure App Service connection-string conventions the platform already recognizes (an App Service connection string named `DefaultConnection`, type SQL Azure, lands on this key automatically). The checked-in default now points at SQL Server LocalDB (`(localdb)\MSSQLLocalDB`, database `andes-agents`, Windows authentication), so a fresh checkout has a connection string that's valid without any local configuration — though a developer using the SQL Server 2025 Docker container must now set `ConnectionStrings:DefaultConnection` explicitly, or the app silently talks to LocalDB instead. The old `SqlDb:ConnectionString` key — and its environment-variable and Key Vault forms — is no longer read at all; anyone running `main` with it configured needs to move the value over. See [Configuration](docs/operations/configuration.md#connectionstringsdefaultconnection).
- Added `Directory.Build.props` and `Directory.Packages.props` (central package management) to `weather-agent/Andes.Agents/`, plus a new `Andes.Agents.Dto` project, so the solution's six projects share one place for build settings and package versions.
- Added `.claude/rules/api-architecture.md`, a portable layering and naming rule for minimal-API solutions shaped `Api → Service → Repository → Entity`, adopted for this repository with the `Andes.Agents` folder layout and its Cosmos-only persistence, embedded prompt, and wire-contract route deviations documented in the rule's appendix.
- Renamed the agent's model provider configuration from `Foundry` to `AzureOpenAI` to make room for the new second provider above; `MicrosoftFoundry` now names the optional Chat Completions deployment. The agent's own deployment, key, and behavior are unchanged.
- The `AzureAd` section is now read through a validated options class, so a missing or contradictory Entra ID setting fails at startup rather than at the first request; `AzureAd:Authority` is accepted as an alternative to setting `AzureAd:Instance` and `AzureAd:TenantId` separately.
- Consolidated six per-exception-type handlers into one exception handler covering every mapped failure; an unhandled (5xx) failure's response no longer echoes any detail or domain problem type, only a trace id — the failure itself still goes to the log.
- Made the repository layer provider-first and Cosmos-owned end to end: `Microsoft.Azure.Cosmos` now resolves in exactly one project (`Andes.Agents.Repository`), which exposes store-agnostic session contracts (`ISessionRepository`, `ISessionMessageRepository`) at its root and keeps every Cosmos-specific type — options, health check, persistence registration, serialization, and the repository implementations — under its own `Cosmos/` folder. Persistence registration moved from the Api project into that folder (`AddAndesCosmosPersistence`, called directly from `Program.cs`), and `CosmosAgentSessionStore`/`CosmosChatHistoryProvider` in the Service layer were renamed to `PersistedAgentSessionStore`/`PersistedChatHistoryProvider` since neither ever depended on the Cosmos SDK. A second store can now be added as a sibling folder without touching the first. No behavior change.
- Replaced DataAnnotations validation with FluentValidation across every options class and request DTO: each type's validation rules now live in an `AbstractValidator<T>` beside the type, wired into `IOptions<T>` through a small adapter and `.ValidateWithFluentValidation().ValidateOnStart()`, so a misconfigured setting still fails at startup with the same guarantees as before. A request that fails validation (e.g. an out-of-range paging parameter on `api/conversations`) now gets a `400` with a per-property `errors` object in the response body, in addition to the existing problem+json shape.
- **Breaking:** a session's continuation id (A2A `contextId`, AG-UI `threadId`) must now be a GUID in hyphenated (`D`) or plain (`N`) form — both hosts already issued `N` ids, so most callers are unaffected, but a client-supplied id of any other shape that previously worked now gets rejected. AG-UI and `api/conversations` return the existing `400` `validation-error`; A2A, which would otherwise turn the rejection into a 500 or an opaque JSON-RPC internal error, now returns `400` on HTTP+JSON or JSON-RPC error `-32602`. **Breaking:** `DateUpdated` is renamed `DateModified` everywhere — `dateModified` in the Cosmos DB session document and the `api/conversations` response, and the `[Core].[Policy]` column (renamed in place, data kept). A session document written before this change reads the new field as its default value until its next save. The agent's default model deployment (`AzureOpenAI:Model`) changed from `rrp-gpt-5.6-luna` to `rr-gpt-5.6-luna`, and SQL Server is now a required dependency at startup rather than only at `/health/ready`, since startup validates the agent catalog against it. See [Sessions and history](docs/conversations/sessions-and-history.md), [Architecture overview](docs/architecture/overview.md#startup-order), and [ADR-0003](docs/adr/0003-database-owned-agent-catalog-and-session-usage.md).
- Every string column in the database is now `nvarchar`: `[Core].[Policy]`'s `PolicyNumber`, `ProductCode`, `Status` and `HolderReference` change from `varchar` at the same lengths, and `CurrencyCode` from fixed-length `char(3)` to `nvarchar(3)`. The `AlterPolicyStringColumnsToNvarchar` migration alters them in place with their data, dropping and re-adding `CK_Policy_Status` and `CK_Policy_CurrencyCode` around the change; both now compare against `N'…'` literals and enforce the same rules. See [Architecture overview](docs/architecture/overview.md#the-corepolicy-table).
